## 파트 1 — 코딩테스트

### 🧩 문자열 내 마음대로 정렬하기 (`CustomSort`)

#### 문제 요약

문자열 배열 `strings`와 정수 `n`이 주어질 때,
각 문자열의 n번째 글자를 기준으로 오름차순 정렬.
n번째 글자가 같은 경우 사전순 정렬.

#### 풀이 코드

```java
package week3;

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.util.Arrays;

public class CustomSort {
  public static void main(String[] args) throws IOException {
    BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
    String[] strings = br.readLine().split(" ");
    int n = Integer.parseInt(br.readLine());

    Arrays.sort(strings, (a, b) -> {
      if (a.charAt(n) == b.charAt(n)) {
        return a.compareTo(b);  // 사전순
      }
      return a.charAt(n) - b.charAt(n);  // n번째 글자 기준
    });

    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < strings.length; i++) {
      if (i > 0) sb.append(" ");
      sb.append(strings[i]);
    }

    System.out.println(sb);
  }
}
```

#### 핵심 아이디어

- `Arrays.sort()` + `Comparator` 람다식 활용
- n번째 글자 비교: `a.charAt(n) - b.charAt(n)`
- 사전순 비교: `a.compareTo(b)`
- 원본 문자열을 버리지 않고 `strings` 배열 자체를 정렬

#### 복잡도 분석

|    | 복잡도             | 이유                          |
|----|-----------------|-----------------------------|
| 시간 | **O(NL log N)** | 정렬 O(N log N) × 문자열 비교 O(L) |
| 공간 | **O(N)**        | 입력 배열 크기                    |

> 💡 **면접 포인트**: 문자열 정렬은 단순히 O(N log N)이 아니라 문자열 길이 L을 고려해 **O(NL log N)**

#### Comparator 핵심 정리

| 리턴값 | 의미           |
|-----|--------------|
| 음수  | a가 앞 (순서 유지) |
| 0   | 순서 유지        |
| 양수  | b가 앞 (순서 교체) |

```java
(a,b)->a -

b  // 오름차순
(a, b) ->b -a  // 내림차순
```

## 파트 2 — Week 3 면접 Q&A

### 🌐 네트워크

#### HTTP vs HTTPS

- HTTP: 평문 데이터 전송
- HTTPS: TLS를 통해 암호화된 데이터 전송
- **비대칭키(공개키)** 로 pre-master secret 전달 → **대칭키(세션키)** 생성 → 실제 데이터 암호화

#### TLS Handshake 흐름

```
1. 클라이언트 → 서버: 암호화 방식 목록 전달
2. 서버 → 클라이언트: 암호화 방식 선택 + 공개키(인증서) 전달
3. 클라이언트 → 서버: 공개키로 암호화한 pre-master secret 전달
4. 양측: pre-master secret으로 세션키(대칭키) 생성
5. 이후 세션키로 데이터 암호화 통신
```

#### TCP 3-Way Handshake

```
클라이언트 → 서버  : SYN      "연결할게"
서버 → 클라이언트  : SYN-ACK  "확인, 나도 연결할게"
클라이언트 → 서버  : ACK      "확인"
```

#### TCP 4-Way Handshake

```
클라이언트 → 서버  : FIN  "나 다 보냈어, 끊을게"
서버 → 클라이언트  : ACK  "알겠어, 잠깐만"
서버 → 클라이언트  : FIN  "나도 다 보냈어, 끊을게"
클라이언트 → 서버  : ACK  "확인, 끊자"
```

> 💡 **4-Way인 이유**: 서버가 ACK와 FIN을 즉시 같이 보낼 수 없음. 남은 데이터를 모두 전송 후 FIN 전송

#### HTTP/1.1 vs HTTP/2.0

|       | HTTP/1.1     | HTTP/2.0       |
|-------|--------------|----------------|
| 처리 방식 | 순차 처리        | 멀티플렉싱          |
| 문제    | HOL Blocking | 해결             |
| 연결    | 요청마다 대기      | 하나의 TCP로 동시 처리 |

### ☕ Java

#### GC (Garbage Collection)

**JVM 힙 구조**

```
Young Generation          Old Generation
┌──────┬────┬────┐        ┌─────────────┐
│ Eden │ S0 │ S1 │   →    │     Old     │
└──────┴────┴────┘        └─────────────┘
```

**GC 과정**

1. Eden 가득 참 → **Minor GC** 발생
2. 살아남은 객체 → S0 또는 S1으로 이동
3. age가 **15** 초과 → Old Generation으로 **Promotion**
4. Old Generation 가득 참 → **Major GC(Full GC)** 발생
5. Major GC 시 **STW(Stop-The-World)** → 모든 스레드 정지 → 버벅임 발생

**G1 GC**

- Java 9부터 기본 GC로 채택
- 힙을 고정 영역이 아닌 작은 **Region**으로 분할
- 가득 찬 Region만 선택적으로 GC → **STW 시간 감소**
