## 파트 1 — 코딩테스트

### 문제: 완주하지 못한 선수

**핵심 아이디어**

- participant를 HashMap에 카운트 +1
- completion을 HashMap에 카운트 -1
- 카운트가 1 남은 사람이 완주하지 못한 선수
- 동명이인을 횟수로 관리하기 때문에 정확하게 처리 가능

**풀이 코드**

```java
package week3;

import java.util.HashMap;
import java.util.Map;

public class MarathonSolver {
  public String solution(String[] participant, String[] completion) {
    Map<String, Integer> map = new HashMap<>();

    // 1. 참가자 카운트 +1
    for (String p : participant) {
      map.put(p, map.getOrDefault(p, 0) + 1);
    }

    // 2. 완주자 카운트 -1
    for (String c : completion) {
      map.put(c, map.get(c) - 1);
    }

    // 3. 카운트가 1 남은 사람이 완주 못한 선수
    for (Map.Entry<String, Integer> entry : map.entrySet()) {
      if (entry.getValue() > 0) {
        return entry.getKey();
      }
    }

    return "";
  }
}
```

**복잡도 분석**

|       | 분석                                                            |
|-------|---------------------------------------------------------------|
| 시간복잡도 | O(3N) → **O(N)** — participant N번, completion N-1번, map N번 순회 |
| 공간복잡도 | **O(N)** — HashMap에 participant 최대 N개 저장                      |

## 파트 2 — Java 실습: TCP 소켓 통신

### 핵심 개념

**3-Way Handshake vs 데이터 전송 분리**

```
[연결 수립 단계] ← 3-Way Handshake
클라이언트  ──── SYN ────────▶ 서버
클라이언트  ◀─── SYN-ACK ──── 서버
클라이언트  ──── ACK ────────▶ 서버
             "우리 연결됐어!"

[데이터 전송 단계] ← 별도로 구현
클라이언트  ──── "Hello Server!" ────▶ 서버
```

**Java 코드 ↔ TCP 동작 매핑**

| Java 코드                         | TCP 동작                  |
|---------------------------------|-------------------------|
| `new ServerSocket(8080)`        | 포트 바인딩, SYN 대기          |
| `server.accept()`               | 3-Way Handshake 완료      |
| `new Socket("localhost", 8080)` | SYN 전송                  |
| `socket.getInputStream()`       | 받는 통로                   |
| `socket.getOutputStream()`      | 보내는 통로                  |
| `out.flush()`                   | 버퍼 → 네트워크로 즉시 전송        |
| `socket.close()`                | 4-Way Handshake (연결 종료) |

### 실습 코드

**서버** `week3/TcpServer.java`

```java
package week3;

import java.io.*;
import java.net.*;

public class TcpServer {
  public static void main(String[] args) throws IOException {

    // 포트 8080에서 대기 — SYN 기다리는 상태
    ServerSocket serverSocket = new ServerSocket(8080);
    System.out.println("서버 시작 - 연결 대기 중...");

    // accept() — 클라이언트 SYN 오면 연결 수락 (SYN-ACK + ACK)
    Socket socket = serverSocket.accept();
    System.out.println("클라이언트 연결됨!");

    // 데이터 수신
    BufferedReader in = new BufferedReader(
      new InputStreamReader(socket.getInputStream())
    );

    String message = in.readLine();
    System.out.println("받은 메시지: " + message);

    // 자원 해제 (4-Way Handshake 발생!)
    in.close();
    socket.close();
    serverSocket.close();
  }
}
```

**클라이언트** `week3/TcpClient.java`

```java
package week3;

import java.io.*;
import java.net.*;

public class TcpClient {
  public static void main(String[] args) throws IOException {

    // 서버에 연결 요청 — SYN 보내는 순간!
    Socket socket = new Socket("localhost", 8080);
    System.out.println("서버에 연결됨!");

    // 데이터 송신
    PrintWriter out = new PrintWriter(
      new OutputStreamWriter(socket.getOutputStream())
    );

    out.println("Hello Server!");
    out.flush(); // 버퍼 비우기 — 안 하면 메시지 안 감!

    // 자원 해제
    out.close();
    socket.close();
  }
}
```

### 실행 흐름

```
서버                          클라이언트
① ServerSocket(8080) 대기
                              ② new Socket() → 3-Way Handshake
                              ③ "서버에 연결됨!" 출력
④ "클라이언트 연결됨!" 출력        
                              ⑤ "Hello Server!" 전송
⑥ 수신 → 출력
```

## 면접 예상 질문

**Q1. HashMap 대신 정렬로도 풀 수 있는데 왜 HashMap을 선택했나요?**
> HashMap은 O(N)으로 시간 효율이 좋지만 O(N) 공간이 필요합니다.
> 정렬은 O(N log N)이지만 공간은 O(1)입니다.
> 입력 크기가 크고 시간이 중요하다면 HashMap, 메모리가 제한적이라면 정렬을 선택합니다.

**Q2. `flush()`를 호출하지 않으면 어떻게 되나요?**
> PrintWriter는 내부적으로 버퍼를 가지고 있습니다.
> flush()를 호출하지 않으면 데이터가 버퍼에만 쌓이고 네트워크로 전송되지 않아
> 서버가 readLine()에서 무한 대기 상태에 빠집니다.
> socket.close() 시 자동 flush되기도 하지만 명시적 호출이 안전합니다.

**Q3. 3-Way Handshake와 데이터 전송의 차이가 무엇인가요?**
> 3-Way Handshake는 연결 수립 단계로 SYN/SYN-ACK/ACK를 주고받으며
> 연결 가능 여부만 확인합니다. Java에서는 accept() 한 줄에 숨어있습니다.
> 실제 데이터 전송은 별도로 InputStream/OutputStream을 통해 구현해야 합니다.

**Q4. ServerSocket과 Socket의 차이가 무엇인가요?**
> ServerSocket은 특정 포트에서 연결 요청을 기다리는 역할을 합니다.
> accept()가 호출되면 실제 통신에 사용할 Socket을 반환합니다.
> Socket은 클라이언트-서버 간 실제 데이터를 주고받는 통로입니다.
