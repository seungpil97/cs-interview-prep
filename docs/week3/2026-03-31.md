## 🧩 파트 1 — 코딩테스트

### 문제: 문자열 압축 (Level 2)

> 문자열 `s`를 앞에서부터 `k`개씩 잘라 반복되는 부분을 숫자로 압축한다.
> 가장 짧은 압축 결과의 **길이**를 반환하라.

**테스트케이스**

| 입력                    | 출력 |
|-----------------------|----|
| `"aabbaccc"`          | 7  |
| `"ababcdcdababcdcd"`  | 9  |
| `"abcabcdede"`        | 8  |
| `"xababcdcdababcdcd"` | 17 |

**제한 조건**

- 1 ≤ s.length ≤ 1,000
- 압축 단위는 1 ~ s.length/2 까지

---

### 풀이 코드

```java
package week3;

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;

/**
 * 문제 설명
 * 문자열 s를 앞에서부터 k개씩 잘라 반복되는 부분을 숫자로 압축한다.
 * 가장 짧은 압축 결과의 길이를 반환하라.
 */
public class StringCompression {
  public static void main(String[] args) throws IOException {
    BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
    String s = br.readLine();
    System.out.println(solution(s));
  }

  private static int solution(String s) {
    int min = s.length();
    for (int k = 1; k <= s.length() / 2; k++) {
      min = Math.min(min, compress(s, k));
    }
    return min;
  }

  private static int compress(String s, int k) {
    StringBuilder sb = new StringBuilder();
    String prev = s.substring(0, k);
    int count = 1;

    for (int i = k; i < s.length(); i += k) {
      String curr = s.substring(i, Math.min(i + k, s.length()));

      if (curr.equals(prev)) {
        count++;
      } else {
        if (count > 1) {
          sb.append(count).append(prev);
        } else {
          sb.append(prev);
        }
        count = 1;
      }
      prev = curr;
    }

    if (count > 1) {
      sb.append(count).append(prev);
    } else {
      sb.append(prev);
    }

    return sb.length();
  }
}
```

---

### 💡 핵심 아이디어

```
k를 1 ~ s.length/2 까지 모두 시도 (브루트포스)
각 k에 대해 이전 조각(prev)과 현재 조각(curr)을 비교
  - 같으면 count++
  - 다르면 count > 1이면 숫자 붙여서 추가, count 리셋
모든 k 중 가장 짧은 압축 길이 반환
```

---

### 📊 복잡도 분석

| 항목    | 복잡도        | 이유                             |
|-------|------------|--------------------------------|
| 시간복잡도 | O(N log N) | 바깥 루프 N/2 × 안쪽 루프 점점 감소 = 조화급수 |
| 공간복잡도 | O(N)       | StringBuilder 최대 원본 길이         |

> **조화급수**: N + N/2 + N/3 + ... = N × (1 + 1/2 + 1/3 + ...) → O(N log N)
> 이중 루프라도 안쪽 루프가 줄어드는 구조면 O(N²)이 아닐 수 있다!

- `main` 안에 모든 로직을 넣지 않고 `solution`, `compress` 메서드로 분리

## 📚 파트 2 — CS 개념 심화

### 1. TLS Handshake

#### 대칭키 vs 비대칭키

|        | 대칭키          | 비대칭키         |
|--------|--------------|--------------|
| 특징     | 잠그는 키 = 여는 키 | 잠그는 키 ≠ 여는 키 |
| 속도     | ✅ 빠름         | ❌ 느림         |
| 전달 안전성 | ❌ 위험         | ✅ 안전         |

#### TLS가 두 방식을 혼합하는 이유

```
비대칭키로 대칭키를 안전하게 전달
→ 이후 통신은 빠른 대칭키로!
```

#### TLS Handshake 전체 흐름

```
1. ClientHello
   클라이언트 → 서버
   "나 이런 암호화 방식 지원해" (목록 전달)

2. ServerHello + 인증서
   서버 → 클라이언트
   자물쇠(공개키) + 공증서(인증서) 전달
   (열쇠=개인키는 서버가 보관!)

3. 인증서 검증
   클라이언트 → CA 서명 확인
   "이 서버 진짜 맞네" ✅

4. 대칭키 교환
   클라이언트 → 대칭키를 공개키로 잠가서 전송
   서버 → 개인키로 열어서 대칭키 획득

5. 이후 통신
   둘 다 같은 대칭키로 빠르게 암호화 통신
```

#### CA(Certificate Authority) 역할

```
공개키가 진짜 해당 서버 것인지 보증하는 공증 기관
브라우저 자물쇠 🔒 아이콘 = CA가 인증한 서버
ex) 디지서트, Let's Encrypt
```

### 2. TCP 흐름 제어 / 혼잡 제어

#### TCP가 나눠서 보내는 이유

```
데이터를 패킷으로 분할 후 순서번호(Sequence Number) 부여
뒤죽박죽 도착해도 번호 보고 순서대로 재조립
```

#### 흐름 제어 — 슬라이딩 윈도우

```
수신자가 받을 수 있는 버퍼 크기(윈도우)를 송신자에게 알려줌
송신자는 윈도우 크기만큼만 전송
→ 수신자 버퍼 오버플로우 방지
```

#### 혼잡 제어 — AIMD

```
패킷 잘 도착 😊 → 조금씩 빠르게 (Additive Increase)
패킷 유실 😱    → 확 줄임 (Multiplicative Decrease)
```

#### 흐름 제어 vs 혼잡 제어

|    | 흐름 제어          | 혼잡 제어        |
|----|----------------|--------------|
| 문제 | 수신자가 너무 느림     | 네트워크가 너무 막힘  |
| 해결 | 수신자 윈도우 크기로 조절 | 패킷 유실 여부로 조절 |
| 주체 | 수신자            | 네트워크         |

### 3. HTTP/1.1 vs HTTP/2 vs HTTP/3

|              | HTTP/1.1       | HTTP/2      | HTTP/3     |
|--------------|----------------|-------------|------------|
| 전송 방식        | 순서대로 (한 번에 하나) | 동시에 (멀티플렉싱) | 동시에        |
| 기반 프로토콜      | TCP            | TCP         | UDP (QUIC) |
| 속도           | 🐢             | 🚀          | 🚀🚀       |
| HOL Blocking | ❌ 있음           | ✅ 해결        | ✅ 완전 해결    |

```
HTTP/1.1 → 앞 요청 막히면 뒤가 다 기다림 (HOL Blocking)
HTTP/2   → 멀티플렉싱으로 하나의 연결에서 여러 요청 동시 처리
HTTP/3   → TCP 3-way Handshake 없이 UDP 기반 QUIC으로 더 빠르게
```
