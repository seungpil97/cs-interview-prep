## 코딩테스트 — 주식 가격

### 문제
초 단위로 기록된 주식 가격 배열이 주어질 때, 각 시점에서 가격이 떨어지지 않은 기간(초)을 구하세요.

### 풀이 1 — 이중 for문 O(N²)
```java
for (int i = 0; i < prices.length; i++) {
    int price = prices[i];
    int count = 0;

    for (int j = i + 1; j < prices.length; j++) {
        count++;
        if (prices[j] < price) break;
    }
    result[i] = count;
}
```

### 풀이 2 — 스택 O(N) (최적화)
```java
Deque<Integer> stack = new ArrayDeque<>();

for (int i = 0; i < prices.length; i++) {
    // 현재 가격이 스택 top의 가격보다 작으면 → 떨어진 것
    while (!stack.isEmpty() && prices[stack.peek()] > prices[i]) {
        int idx = stack.pop();
        result[idx] = i - idx;
    }
    stack.push(i);
}

// 스택에 남은 건 끝까지 안 떨어진 것
while (!stack.isEmpty()) {
    int idx = stack.pop();
    result[idx] = prices.length - 1 - idx;
}
```

### 핵심 아이디어
- 스택에 값이 아닌 **인덱스**를 저장
- 현재 가격 < 스택 top의 가격 → 떨어진 것 → `result[idx] = i - idx`
- for문 끝나고 스택에 남은 것 → 끝까지 안 떨어진 것 → `result[idx] = length - 1 - idx`

### 복잡도
| 풀이 | 시간복잡도 | 공간복잡도 |
|------|-----------|-----------|
| 이중 for문 | O(N²) | O(N) |
| 스택 | O(N) | O(N) |

### 분할상환 분석 (Amortized Analysis)
for 안에 while이 있어도 O(N)인 이유:
- 각 인덱스는 스택에 **딱 1번 push, 1번 pop**
- 전체 push 횟수 = N번, 전체 pop 횟수 = N번 이하
- 총 연산 = O(2N) = **O(N)**

## Java 실습 — 데드락 (Deadlock)

### 데드락 발생 코드
```java
static Object lock1 = new Object();
static Object lock2 = new Object();

Thread t1 = new Thread(() -> {
    synchronized (lock1) {   // lock1 획득
        synchronized (lock2) { // lock2 기다림
        }
    }
});

Thread t2 = new Thread(() -> {
    synchronized (lock2) {   // lock2 획득
        synchronized (lock1) { // lock1 기다림 → 데드락!
        }
    }
});
```

### 데드락 발생 이유
```
t1: lock1 점유 → lock2 기다림
t2: lock2 점유 → lock1 기다림
→ 서로 기다리다 영원히 멈춤 (순환대기)
```

4가지 조건 모두 성립:
1. 상호배제 — synchronized라 한 번에 하나만 lock 가능
2. 점유대기 — lock 들고 다른 lock 기다림
3. 비선점 — lock 강제로 못 빼앗음
4. 순환대기 — t1 → t2 → t1 순환

### 해결 — 락 획득 순서 통일
```java
Thread t2 = new Thread(() -> {
    synchronized (lock1) {   // lock1 먼저 (순서 통일!)
        synchronized (lock2) { // lock2 나중
        }
    }
});
```

### 왜 해결되나?
```
t1, t2 둘 다 lock1 원함
       ↓
먼저 획득한 쪽이 lock1 → lock2 순서로 작업
       ↓
끝나면 해제 → 대기하던 쪽이 lock1 획득
       ↓
순환 없음 → 데드락 없음
```

> 핵심: 락 획득 순서를 통일하면 **순환대기** 조건이 깨져서 데드락이 발생하지 않는다.
> 데드락 4가지 조건 중 하나만 깨도 데드락은 사라진다.

### 주의
- `t1.start()`를 먼저 호출해도 실행 순서는 **OS 스케줄러가 결정**
- 매번 실행 순서가 달라질 수 있음
- 그래서 어떤 순서로 실행되든 데드락이 안 생기게 설계하는 것이 중요
