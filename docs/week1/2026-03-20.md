## 코딩테스트 — 기능 개발

### 문제
각 기능의 현재 진도와 하루 작업량이 주어질 때, 각 배포마다 몇 개의 기능이 배포되는지 구하세요. 앞의 기능이 완료되지 않으면 뒤의 기능도 배포 불가

### 풀이 — O(N)
```java
int[] days = new int[progresses.length];

for (int i = 0; i < progresses.length; i++) {
    int progress = Integer.parseInt(progresses[i]);
    int speed = Integer.parseInt(speeds[i]);
    days[i] = (100 - progress + speed - 1) / speed;  // 올림 공식
}

int maxDay = days[0];
int count = 0;
List<Integer> results = new ArrayList<>();

for (int day : days) {
    if (day <= maxDay) {
        count++;
    } else {
        results.add(count);
        maxDay = day;
        count = 1;
    }
}
results.add(count);
```

### 핵심 아이디어
- 완료일을 먼저 계산 → 앞 기능의 완료일보다 작거나 같으면 같이 배포
- 올림 공식: `(100 - progress + speed - 1) / speed`
  - 나머지가 있을 때 자동으로 올림 처리
  - `Math.ceil()` 없이 정수 연산만으로 올림 구현

### 복잡도
- 시간복잡도: O(N)
- 공간복잡도: O(N) — days 배열 + results 리스트

## 이번 주 전체 복습 — 면접 Q&A

### Q. 프로세스와 스레드의 차이는?
> 프로세스는 실행 중인 프로그램으로 Code/Data/Heap/Stack 4개의 메모리 영역을 가집니다. 스레드는 프로세스 안에서 실행되는 작업 단위로, 여러 스레드가 Code/Data/Heap을 공유하고 Stack만 각자 독립적으로 가집니다. Heap을 공유하기 때문에 여러 스레드가 동시에 같은 객체에 접근하면 Race Condition이 발생할 수 있고, 이를 해결하기 위해 synchronized 같은 동기화가 필요합니다.

### Q. 데드락이란? 발생 조건 4가지는?
> 데드락은 두 개 이상의 스레드가 서로의 자원을 기다리며 영원히 멈추는 상태입니다.

발생 조건 4가지 (모두 동시에 성립해야 발생):
1. **상호배제** — 한 번에 하나의 스레드만 자원 사용 가능
2. **점유대기** — 자원을 들고 있으면서 다른 자원을 기다림
3. **비선점** — 남의 자원을 강제로 빼앗을 수 없음
4. **순환대기** — t1이 t2를 기다리고, t2가 t1을 기다리는 순환

> 해결법: 락 획득 순서를 통일하면 순환대기 조건이 깨져 데드락이 사라집니다.

### Q. Round Robin의 장단점은? Time Quantum 크기에 따른 문제는?
> Round Robin은 각 프로세스에 Time Quantum을 할당해 돌아가며 실행하는 방식입니다. Starvation이 없다는 장점이 있지만, Time Quantum이 너무 작으면 컨텍스트 스위칭 오버헤드가 증가하고, 너무 크면 FCFS와 다를 바 없어 짧은 프로세스의 대기시간이 길어집니다.

### Q. SJF의 단점과 해결 방법은?
> SJF는 짧은 작업만 계속 실행되어 긴 작업이 영원히 실행되지 못하는 Starvation(기아 현상)이 발생합니다. 이를 해결하기 위해 에이징(Aging) 기법을 사용합니다. 오래 기다린 프로세스의 우선순위를 점점 높여서 결국 실행될 수 있도록 보장합니다.
