# 2026-03-17 학습 정리

## 코딩테스트 — 올바른 괄호 문자열

### 문제
주어진 문자열이 올바른 괄호 문자열인지 확인

### 최종 풀이
```java
int count = 0;

for (int i = 0; i < input.length(); i++) {
    char c = input.charAt(i);

    if (c == ')' && count == 0) {
        System.out.println(false);
        return;
    }

    if (c == '(') count++;
    else count--;
}

System.out.println(count == 0);
```

### 핵심 아이디어
- `(` 를 만나면 count++, `)` 를 만나면 count--
- `)` 를 만났을 때 count가 0이면 즉시 false (짝 없는 닫는 괄호)
- 끝까지 순회 후 count == 0 이면 true

### 복잡도
- 시간복잡도: O(N) — 문자열 길이만큼 순회
- 공간복잡도: O(1) — count 변수 하나만 사용

### 학습 포인트
- 처음엔 `Deque<Character>` 스택에 모든 문자를 넣었으나, `(` 개수만 카운팅하면 충분
- 스택 방식은 O(N) 공간, 카운터 방식은 O(1) 공간 — 최적화 포인트

## OS 개념 — 프로세스 vs 스레드

### 프로세스 메모리 구조
| 영역 | 내용 |
|------|------|
| Code | 실행할 코드 |
| Data | 전역변수, static 변수 |
| Heap | new로 생성한 객체 |
| Stack | 메서드 호출, 지역변수 |

### 스레드의 메모리 공유
- **공유**: Code, Data, Heap
- **독립**: Stack (스레드마다 각자 보유)

### Race Condition (경쟁 조건)
- 여러 스레드가 공유 자원(Data/Heap)에 동시 접근할 때 발생
- `count++` 는 실제로 3단계 (읽기 → 연산 → 저장)
- 두 스레드가 동시에 읽으면 연산 결과가 덮어씌워짐

```java
// 문제 코드
static int count = 0;  // Data 영역 — 공유됨

// t1, t2 동시 실행 시 count가 2000이 아닐 수 있음
```

### 해결 — 동기화 (synchronized)
```java
// 한 번에 하나의 스레드만 실행
synchronized (this) {
    count++;
}

// 또는 메서드에 선언
public synchronized void increment() {
    count++;
}
```

### 데드락 (Deadlock)
락을 잘못 사용하면 서로 대기하는 교착 상태 발생

**발생 조건 4가지 (모두 성립해야 발생)**
1. **상호배제** — 한 번에 하나의 스레드만 자원 사용 가능
2. **점유대기** — 자원을 들고 있으면서 다른 자원을 기다림
3. **비선점** — 남의 자원을 강제로 빼앗을 수 없음
4. **순환대기** — t1이 t2를 기다리고, t2가 t1을 기다리는 순환
