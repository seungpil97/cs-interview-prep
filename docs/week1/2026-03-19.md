## 코딩테스트 — 탑

### 문제
수평 직선에 탑들이 세워져 있을 때, 각 탑에서 레이저를 왼쪽으로 쏘면 처음으로 수신하는 탑의 인덱스를 구하세요. (자신보다 높은 탑이 수신, 없으면 0)

### 풀이 — 스택 O(N)
```java
public static int[] solution(int[] heights) {

    int[] result = new int[heights.length];
    Deque<Integer> stack = new ArrayDeque<>();

    for (int i = 0; i < heights.length; i++) {

        // 현재보다 작거나 같은 탑은 수신 불가 → pop
        while (!stack.isEmpty() && heights[stack.peek()] <= heights[i]) {
            stack.pop();
        }

        if (stack.isEmpty()) {
            result[i] = 0;
        } else {
            result[i] = stack.peek() + 1;  // 1-based index
        }

        stack.push(i);
    }

    return result;
}
```

### 핵심 아이디어
- 스택에 인덱스 저장
- 현재 탑보다 작거나 같은 탑은 레이저 수신 불가 → pop
- 스택 top이 처음으로 높은 탑 → `stack.peek() + 1`
- `<=` 를 쓰는 이유: 같은 높이는 수신 불가 (strictly 높아야 수신)

### 복잡도
- 시간복잡도: O(N)
- 공간복잡도: O(N) — 스택 + result 배열

## OS 개념 — CPU 스케줄링

### CPU 스케줄링이란?
CPU는 한 번에 하나의 프로세스만 실행 가능. 여러 프로세스 중 누구에게 CPU를 줄지 결정하는 것

### 스케줄링 알고리즘

| 알고리즘 | 방식 | 장점 | 단점 |
|---------|------|------|------|
| FCFS | 먼저 온 순서대로 | 구현 단순 | Convoy Effect |
| SJF | 짧은 작업 먼저 | 평균 대기시간 최소 | Starvation |
| Round Robin | Time Quantum씩 돌아가며 | Starvation 없음 | 컨텍스트 스위칭 오버헤드 |
| 우선순위 | 우선순위 높은 것 먼저 | 중요한 작업 먼저 | Starvation |

### FCFS — Convoy Effect
```
P1 (100ms) → P2 (1ms) → P3 (1ms)

P2, P3는 1ms짜리인데 P1 때문에 100ms 기다려야 함
→ 긴 작업이 짧은 작업을 막는 현상
```

### Round Robin — Time Quantum
```
Time Quantum = 4ms

P1 (10ms) ── 4ms 실행 → 대기
P2 (3ms)  ── 3ms 실행 → 완료
P3 (6ms)  ── 4ms 실행 → 대기
P1 (6ms)  ── 4ms 실행 → 대기
...
```

Time Quantum 크기에 따른 트레이드오프:
- 너무 크면 → FCFS와 다를 바 없음, 짧은 프로세스 대기시간 증가
- 너무 작으면 → 컨텍스트 스위칭 오버헤드 증가 (보통 10~100ms)

### SJF — Starvation & 에이징(Aging)
```
P1 (100ms) 대기 중
P2 (1ms), P3 (2ms), P4 (1ms) ... 계속 들어오면
→ P1은 영원히 실행 못 할 수도 있음 (Starvation)
```

해결법 — 에이징(Aging):
- 오래 기다린 프로세스의 우선순위를 점점 올려줌
- 결국 가장 높은 우선순위가 되어 실행됨
