### 핵심 아이디어

- `target - nums[i]` = 짝꿍값
- map에 짝꿍이 있으면 → 정답
- 없으면 → map에 현재 값 저장 후 계속

## OS 개념 — 가상메모리

### 가상메모리란?

각 프로세스가 자기만의 독립된 메모리 공간을 가진 것처럼 착각하게 만드는 것

```
실제 물리 메모리 (RAM): 16GB

프로세스 A → "나 혼자 0~16GB 다 쓸 수 있어" (착각)
프로세스 B → "나 혼자 0~16GB 다 쓸 수 있어" (착각)

실제로는 OS가 가상주소 → 물리주소 변환
```

### 페이징 (Paging)

가상메모리를 구현하는 방식

```
가상 메모리 → 페이지(Page) 단위로 자름
물리 메모리 → 프레임(Frame) 단위로 자름
페이지 테이블로 가상주소 → 물리주소 매핑
```

### TLB (Translation Lookaside Buffer)

- 페이지 테이블 접근 시 메모리를 2번 접근해야 하는 문제 해결
- 자주 쓰는 페이지 매핑을 캐싱해두는 하드웨어
- TLB 히트 → 빠른 주소 변환
- TLB 미스 → 페이지 테이블 접근 (느림)

### 스왑 (Swap)

RAM이 부족할 때 디스크를 활용하는 것

```
잘 안 쓰는 페이지 → 디스크로 내보냄 (swap out)
필요한 페이지    → 디스크에서 RAM으로 가져옴 (swap in)

RAM 접근 속도  → 수십 나노초 (ns)
디스크 접근 속도 → 수 밀리초 (ms)
→ 약 100,000배 차이 → 스왑 많으면 프로그램 느려짐
```

### 페이지 폴트 (Page Fault)

필요한 페이지가 RAM에 없을 때 발생하는 이벤트

```
프로세스가 가상주소 접근
       ↓
RAM에 있음 → 바로 접근 (정상)
RAM에 없음 → 페이지 폴트 발생!
       ↓
OS가 디스크에서 해당 페이지를 RAM으로 가져옴
       ↓
다시 접근
```

### 스래싱 (Thrashing)

페이지 폴트가 너무 자주 발생해 프로그램이 극도로 느려지는 현상

### Java 연결

```
JVM 힙을 RAM 크기 이상으로 설정하면
→ 스왑 발생 → 프로그램 느려짐

실무에서 RAM: 16GB → -Xmx12g 정도로 설정
```

# 가상메모리 면접 예상 질문 모범답안

## Q1. 가상메모리가 왜 필요한가요?

> 물리 메모리(RAM)는 크기가 제한되어 있고 여러 프로세스가 동시에 실행됩니다. 가상메모리가 없으면 프로세스들이 물리 메모리 주소를 직접
> 사용하게 되어 서로의 메모리를 침범할 수 있습니다. 가상메모리를 사용하면 각 프로세스가 독립된 가상 주소 공간을 가지게 되어 다른 프로세스의
> 메모리를 침범할 수 없고, RAM보다 큰 메모리도 사용할 수 있습니다.

---

## Q2. 페이징이란 무엇인가요?

> 페이징은 가상메모리를 구현하는 방식입니다. 가상 메모리와 물리 메모리를 동일한 크기의 단위로 나누는데, 가상 메모리의 단위를 페이지, 물리
> 메모리의 단위를 프레임이라고 합니다. 페이지 테이블을 통해 가상 주소를 물리 주소로 변환합니다. 이를 통해 연속되지 않은 물리 메모리 공간도
> 프로세스에게 연속된 것처럼 보이게 할 수 있습니다.

---

## Q3. 페이지 폴트가 무엇인가요?

> 페이지 폴트는 프로세스가 접근하려는 페이지가 현재 RAM에 없을 때 발생하는 이벤트입니다. 페이지 폴트가 발생하면 OS가 디스크에서 해당
> 페이지를 RAM으로 가져옵니다. RAM과 디스크의 접근 속도 차이가 약 100,000배이기 때문에 페이지 폴트가 자주 발생하면 프로그램 성능이
> 크게 저하됩니다. 페이지 폴트가 극도로 자주 발생하는 상태를 스래싱(Thrashing)이라고 합니다.

---

## Q4. JVM 힙을 너무 크게 설정하면 어떤 문제가 생기나요?

> JVM 힙 크기가 RAM을 초과하면 OS가 스왑을 사용하게 됩니다. 스왑은 RAM 대신 디스크를 메모리로 활용하는 것인데, 디스크 접근
> 속도가 RAM보다 약 100,000배 느리기 때문에 GC가 동작할 때마다 디스크 I/O가 발생해 애플리케이션 응답 속도가 크게 느려집니다.
> 그래서 실무에서는 JVM 힙 최대값(-Xmx)을 RAM 크기의 70~80% 이내로 설정하는 것이 권장됩니다.

## 꼬리질문 대비

**Q. TLB가 뭔가요?**
> 페이지 테이블은 메모리에 있어서 주소 변환 시 메모리를 2번 접근해야 합니다. TLB는 자주 사용하는 페이지 매핑을 캐싱해두는 하드웨어로,
> TLB 히트 시 메모리 접근 없이 빠르게 주소 변환이 가능합니다.

**Q. 스래싱을 어떻게 해결하나요?**
> 프로세스에 충분한 메모리를 할당하거나, 동시에 실행되는 프로세스 수를 줄이거나, RAM을 증설하는 방법으로 해결할 수 있습니다.
