## 코딩테스트 — 문자열 뒤집기

### 문제

문자열을 뒤집어서 반환하세요.

### 풀이 1 — StringBuilder O(N)

```java
StringBuilder sb = new StringBuilder();
sb.

append(input);
sb.

reverse();
System.out.

println(sb);
```

### 풀이 2 — 직접 구현 O(N) / 공간 O(1)

```java
char[] chars = input.toCharArray();
  int left = 0, right = chars.length - 1;

while(left<right){
char temp = chars[left];
chars[left]=chars[right];
chars[right]=temp;
left++;
right--;
  }
  System.out.

println(new String(chars));
```

### 복잡도 비교

| 풀이            | 시간복잡도 | 공간복잡도 |
|---------------|-------|-------|
| StringBuilder | O(N)  | O(N)  |
| 직접 구현         | O(N)  | O(1)  |

> 면접에서 "더 최적화할 수 있나요?" → 직접 구현 방식으로 공간복잡도 O(1) 가능

## OS 심화 — JVM 힙 구조 & GC

### JVM 힙 구조

```
JVM Heap
┌─────────────────────────────────────────┐
│  Young Generation        │ Old          │
│  ┌──────┬──────┬──────┐  │ Generation   │
│  │ Eden │  S0  │  S1  │  │              │
│  └──────┴──────┴──────┘  │              │
└─────────────────────────────────────────┘
+ Metaspace (클래스 메타데이터, 클래스 정보 저장)
```

| 영역        | 설명                          |
|-----------|-----------------------------|
| Eden      | new로 객체가 처음 생성되는 곳          |
| S0/S1     | Survivor 영역, Eden에서 살아남은 객체 |
| Old       | 오래 살아남은 객체 (age 15 이상)      |
| Metaspace | 클래스 메타데이터 저장                |

### GC 동작 과정

```
1. new 객체 생성 → Eden에 저장
2. Eden 꽉 참 → Minor GC 발생
   살아남은 객체 → S0 이동 (age = 1)
3. 또 Minor GC 발생
   Eden + S0 살아남은 객체 → S1 이동 (age = 2)
4. 반복하다가 age 15 이상 → Old Generation 이동 (프로모션)
```

```
Eden → Minor GC → S0 → S1 → S0 → ... → Old
                  age1  age2  age3       age15+
```

### GC 종류

| GC       | 대상               | 속도 | 발생 빈도 |
|----------|------------------|----|-------|
| Minor GC | Young Generation | 빠름 | 자주    |
| Major GC | Old Generation   | 느림 | 가끔    |

### STW (Stop The World)

GC가 동작하는 동안 GC 스레드 외 모든 애플리케이션 스레드가 멈추는 현상

**왜 멈춰야 하나?**
> GC가 객체를 정리하는 도중 다른 스레드가 객체를 새로 만들거나 참조를 바꾸면 GC가 잘못된 객체를 수거할 수 있음

**실무 영향:**

```
Minor GC → STW 짧음 (수 ms)
Major GC → STW 길음 (수백 ms ~ 수 초)
→ Major GC 발생 시 서버 응답이 갑자기 느려짐
```

### 최신 GC

| GC          | 특징                | 기본 적용      |
|-------------|-------------------|------------|
| Serial GC   | 단순, 싱글스레드         | -          |
| Parallel GC | 멀티스레드 GC          | Java 8 기본  |
| G1 GC       | STW를 짧게 여러 번으로 나눔 | Java 9+ 기본 |
| ZGC         | STW 1ms 이하 목표     | Java 15+   |

> Java 17 기준 기본 GC = G1 GC

# JVM 힙 & GC 면접 예상 질문 모범답안

## Q1. JVM 힙 구조를 설명해주세요.

> JVM 힙은 Young Generation, Old Generation, Metaspace로 나뉩니다. Young Generation은 다시
> Eden과 Survivor 영역(S0, S1)으로 나뉘는데, new로 생성된 객체는 Eden에 저장됩니다. GC에서 살아남은 객체는
> Survivor 영역을 오가며 age가 증가하고, age가 15 이상이 되면 Old Generation으로 이동합니다. Metaspace는
> 클래스 메타데이터가 저장되는 영역으로 Java 8부터 힙 외부에 위치합니다.

---

## Q2. GC 동작 과정을 설명해주세요.

> Eden 영역이 꽉 차면 Minor GC가 발생합니다. 살아남은 객체는 Survivor 영역으로 이동하고 age가 1 증가합니다. Minor
> GC가 반복될 때마다 S0과 S1을 번갈아가며 살아남은 객체를 이동시킵니다. age가 15 이상이 되면 Old Generation으로
> 프로모션됩니다. Old Generation이 꽉 차면 Major GC가 발생하는데, Minor GC보다 훨씬 느리고 STW 시간이 길어 성능에
> 영향을 줍니다.

---

## Q3. STW(Stop The World)가 무엇인가요?

> STW는 GC가 동작하는 동안 GC 스레드를 제외한 모든 애플리케이션 스레드가 멈추는 현상입니다. GC가 객체를 정리하는 도중 다른 스레드가
> 객체를 생성하거나 참조를 변경하면 GC가 잘못된 객체를 수거할 수 있기 때문에 필요합니다. Minor GC의 STW는 수 밀리초로 짧지만,
> Major GC는 수백 밀리초에서 수 초까지 길어질 수 있어 서버 응답이 갑자기 느려지는 원인이 됩니다.

---

## Q4. G1 GC가 기존 GC와 다른 점은 무엇인가요?

> 기존 GC는 힙을 Young/Old로 물리적으로 나누고 한 영역 전체를 한 번에 청소해 STW가 길게 발생했습니다. G1 GC는 힙을 동일한
> 크기의 Region으로 나누고 가비지가 많은 Region부터 우선 수거합니다. STW를 짧게 여러 번으로 나눠 발생시키기 때문에 응답 지연을
> 예측 가능한 수준으로 제어할 수 있습니다. Java 9부터 기본 GC로 채택되었습니다.

---

## 꼬리질문 대비

**Q. Minor GC와 Major GC의 차이는?**
> Minor GC는 Young Generation만 청소하며 빠르게 자주 발생합니다. Major GC는 Old Generation을 청소하며
> 느리고 STW가 길어 성능에 더 큰 영향을 줍니다.

**Q. Metaspace가 Java 8에서 바뀐 이유는?**
> Java 7까지는 PermGen이라는 힙 내부 영역에 클래스 메타데이터를 저장했는데, 크기가 고정되어 있어 클래스가 많아지면
> OutOfMemoryError가 자주 발생했습니다. Java 8부터 Metaspace로 대체되어 힙 외부 네이티브 메모리를 사용하고 필요에 따라
> 자동으로 크기가 조절됩니다.

**Q. GC 튜닝을 해본 적 있나요? (1년차 대비용)**
> 직접 튜닝 경험은 없지만, JVM 힙 구조와 GC 동작 원리를 이해하고 있습니다. Old Generation이 자주 꽉 차거나 Major
> GC가 자주 발생한다면 힙 크기 조정(-Xmx)이나 객체 생성 패턴을 점검해볼 것입니다.
