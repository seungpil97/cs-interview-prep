## 코딩테스트 — 문자열 압축

### 문제
문자열을 앞에서부터 같은 문자가 연속으로 반복되는 경우 반복 횟수 + 문자로 압축.
1개인 경우 숫자 생략.

```
"aaabbcc" → "3a2b2c"
"abc"     → "abc"
"aaaa"    → "4a"
```

### 풀이 코드

```java
package week2;

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;

public class StringCompression {

  public static void main(String[] args) throws IOException {
    BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
    String input = br.readLine();

    StringBuilder sb = new StringBuilder();
    char currentToken = input.charAt(0);
    int count = 1;

    for (int i = 1; i < input.length(); i++) {
      char token = input.charAt(i);

      if (currentToken == token) {
        count++;
      } else {
        flush(sb, count, currentToken);
        count = 1;
        currentToken = token;
      }
    }
    flush(sb, count, currentToken);

    System.out.println(sb);
  }

  private static void flush(StringBuilder sb, int count, char ch) {
    if (count > 1) sb.append(count);
    sb.append(ch);
  }
}
```

### 핵심 아이디어
- 현재 문자(`currentToken`)와 다음 문자를 비교하며 그룹 카운트
- 문자가 바뀌는 순간 flush (카운트 + 문자 추가)
- **루프 종료 후 마지막 그룹 flush 필수** ← 놓치기 쉬운 엣지 케이스
- flush 로직 중복 제거 → 메서드 분리

### 복잡도 분석
| | 복잡도 | 이유 |
|---|---|---|
| 시간 | O(N) | 문자열을 한 번 순회 |
| 공간 | O(N) | 결과 StringBuilder가 최대 N만큼 증가 |

> 시간 O(N) 이하는 불가능 (문자열을 한 번은 반드시 읽어야 함) → **이미 최적**

## CS 개념 — GC 실습 (JVM GC 로그 분석)

### 실습 코드

```java
package week2;

public class GCDemo {
    public static void main(String[] args) {
        for (int i = 0; i < 1_000_000; i++) {
            String s = new String("garbage" + i);
        }
        System.out.println("Done");
    }
}
```

**JVM 옵션:** `-Xms32m -Xmx64m -verbose:gc`

### 실제 GC 로그

```
[0.012s][info][gc] Using G1
[0.106s][info][gc] GC(0) Pause Young (Normal) (G1 Evacuation Pause) 14M->1M(34M) 0.736ms
[0.115s][info][gc] GC(1) Pause Young (Normal) (G1 Evacuation Pause) 19M->1M(34M) 0.601ms
Done
```

### 로그 분석

| 항목 | 의미 |
|---|---|
| `Using G1` | Java 17 기본 GC인 G1 GC 사용 |
| `Pause Young` | Minor GC 발생 (Young Generation 대상) |
| `(Normal)` | Eden이 꽉 차서 발생한 일반적인 GC |
| `G1 Evacuation Pause` | 살아있는 객체를 다른 Region으로 대피 |
| `14M->1M(34M)` | GC 전 14MB → GC 후 1MB (힙 전체 34MB) |
| `0.736ms` | STW 시간 (0.0007초, 사용자가 못 느끼는 수준) |

### 관찰 포인트
1. **Minor GC 2번만 발생** — 100만 개 객체가 대부분 Young에서 단명 처리됨
2. **Major GC 없음** — Old Generation까지 Promotion된 객체 없음
3. **STW 0.7ms** — 매우 짧은 정지 시간

### G1 GC 핵심 개념

**기존 GC vs G1 GC**

```
기존 GC: [ ----Young(고정)---- | --------Old(고정)-------- ]

G1 GC:  [ E ][ E ][ S ][ O ][ E ][ O ]
        [ O ][ E ][ S ][ E ][ O ][ E ]
        (Region 단위로 동적 관리, Young/Old 개념은 유지)
```

| | 기존 GC | G1 GC |
|---|---|---|
| Young/Old 구분 | 있음 | 있음 |
| 영역 크기 | 고정 | 동적 (Region 단위) |
| STW 예측 | 어려움 | 가능 (`-XX:MaxGCPauseMillis`) |
| 적합한 힙 크기 | 소~중형 | 대형 (4GB 이상) |

### GC 종류 흐름
`Serial → Parallel → CMS → G1`

### StringBuilder vs String + 연산

| | String += | StringBuilder |
|---|---|---|
| 불변성 | Immutable (매번 새 객체 생성) | Mutable (내부 버퍼에 추가) |
| 시간복잡도 | O(N²) | O(N) |
| 사용 | 단순 연결 1~2회 | 반복 문자열 조작 |

## 면접 예상 질문

**Q1. StringBuilder를 쓴 이유는?**
> Java의 String은 불변 객체(Immutable)이기 때문에 `+=` 연산 시 매번 새로운 객체가 힙에 생성되고 기존 객체는 GC 대상이 됩니다. N번 반복하면 O(N²) 시간이 소요됩니다. StringBuilder는 가변(Mutable) 객체로 내부 버퍼에 문자를 추가하므로 O(N)으로 처리할 수 있습니다.

**Q2. StringBuffer와 StringBuilder 차이는?**
> StringBuffer는 synchronized 키워드로 thread-safe하지만 성능이 느리고, StringBuilder는 동기화가 없어 단일 스레드에서 빠릅니다. 멀티 스레드 환경이 아니라면 StringBuilder를 사용하는 것이 일반적입니다.

**Q3. GC 튜닝 시 어떤 지표를 보나요?**
> 힙 사용량, STW 시간, GC 발생 빈도 세 가지를 주요 지표로 봅니다. `-verbose:gc` 또는 GC 로그 파일로 확인할 수 있습니다.

**Q4. G1 GC가 기존 GC와 다른 점은?**
> 기존 GC는 힙을 Young/Old로 물리적으로 고정 분할하지만, G1은 힙을 작은 Region으로 나눠 동적으로 역할을 부여합니다. 가비지가 많은 Region을 우선 수집(Garbage First)하고, `-XX:MaxGCPauseMillis`로 STW 목표 시간을 설정할 수 있어 대용량 힙에서 유리합니다.
